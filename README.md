# 秋田ニュース＆イベント

秋田県のニュースと催し物のRSSを自動で集め、短い要約と分類を付けて静的サイトとして公開するツール。
GitHub Actions が6時間ごとに走り、GitHub Pages が更新される。

- サイト: https://mifune39428.github.io/akita-news/
- 更新: 日本時間の 3時 / 9時 / 15時 / 21時（GitHub Actions の cron）

## しくみ

```
RSS 9本 ──> collect.py ──> Gemini(→Groq→Claude→OpenAI) ──> docs/articles.json ──> GitHub Pages
         重複除去・期間絞り込み   要約＋分類・催し物判定・除外判定        静的サイトが読む
                              ＋サムネイル取得／秋田市の天気
```

- 原文の本文は保存も掲載もしない。**独自の要約・出典名・原文リンク・サムネイル**だけを持つ。
- LLMが秋田と無関係と判断した記事（秋田犬の県外の話題、「秋田」姓の人物、広告など）は自動で落とす。
- **事件・事故など気の重くなる話題は載せない**（`negative` 判定）。ただし大雨注意報やクマの目撃情報のような
  「これから身を守るための情報」は残す。
- これから参加できる催しは `kind: event` として、サイト上で「イベント」に絞り込める。
- 各記事にサムネイルを付ける。RSSの中の画像 →（無ければ）元ページの `og:image` の順に探し、
  それでも無い記事は同じ大きさの代替の絵（🏮 / 📅）を出して一覧に穴を空けない。
- Googleニュース経由の記事は**元媒体のURLに戻してから**掲載する（リンク先も画像取得もそのほうが良いため）。
- トップに**秋田市の天気**（今日・明日、6時間ごとの降水確率、10日間）を出す。
- どのLLMも使えなかった分は保存せず、次の実行で拾い直す（生煮えの記事を出さないため）。

## 収集元

- 県内媒体の直接のRSS: 秋田魁新報 / AAB秋田朝日放送 / 秋田経済新聞
- Google ニュース検索のRSS: 「秋田県」「秋田＋イベント・祭り・フェス」「県内7市」、
  および ABS秋田放送・AKT秋田テレビ・NHK秋田（自前のRSSが無いのでサイト指定で拾う）

Google ニュース経由の記事は `<source>` から実際の媒体名を取り出し、
見出し末尾の「 - 媒体名」を落として掲載する。転送URLは掲載前に元媒体のURLへ戻している
（転送ページに埋まっている署名を Google の `batchexecute` に投げると元URLが返る。
仕様が変わって取れなくなったら転送URLのまま載るだけで、リンクとしては壊れない）。

## 天気

- **天気と降水確率は気象庁**（`bosai/forecast/data/forecast/050000.json`）。
  今日・明日は「沿岸」区域の天気文と**6時間ごとの降水確率**、3日目以降は週間予報。
  気象庁は3時間ごとの降水確率を公表していないので、公式の6時間刻みに合わせている。
- **気温**と、気象庁の週間予報より先の日（9〜10日目）は **Open-Meteo**（APIキー不要）。
  数値予報の値なので、その日の行には「目安」と付けている。
- 表示に使う絵文字と言い回しは `collect.py` 側で気象庁のテロップ番号から作る（`JMA_TELOP`）。
- 終わったコマは表示時に落とし、自動更新が止まって予報が古くなったときはパネルごと隠す。
- **tenki.jp はリンクのみ**。同サイトの利用規約 第8条が、ブラウザ・RSSリーダー以外での情報取得と、
  承認のない複製・私的利用を超える使用を禁じているため、データは取得しない（リンクは第6条で原則自由）。

## 設定

- **GitHub Secrets**: `GEMINI_API_KEY` は必須。`GROQ_API_KEY` を入れておくとGeminiの無料枠が切れても止まらない。
  `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` は任意。
- **ローカル実行**: このフォルダの `.env` に同じキーを書く（gitignore 済み）。

## 調整しどころ（`collect.py` の定数）

- `INTAKE_DAYS = 3` — 何日前までの記事を取り込むか
- `MAX_NEW_PER_RUN = 40` — 1回の実行で要約する上限（無料枠を使い切らないための蓋）
- `EVENT_QUOTA = 10` — そのうちイベント検索の記事に確保する枠
- `BACKFILL_PER_RUN = 40` — 1回の実行で、過去記事のサムネイルを取りに行く件数
- `BATCH_SIZE = 5` — 1回のLLM呼び出しでまとめる記事数（Groqの分間トークン制限に合わせてある）
- `KEEP_DAYS = 21` / `KEEP_DAYS_EVENT = 45` / `KEEP_MAX = 400` — サイトに残す期間と件数
- `BLOCK_SOURCES` — まとめサイトなど、出典名で丸ごと落としたい媒体
- `DOMAIN_NAMES` — Google ニュースの出典がドメインのまま入ってくる媒体の表示名

収集元を増やすときは `feeds.json` に足すだけでよい。
`hint` に `event` を入れたフィードは催し物として拾われやすくなる。

## 著作権について

各記事の権利は出典元にある。このサイトが持つのは自動生成した見出しと要約、
出典名、原文へのリンクだけで、本文の全訳や転載はしない。掲載停止の依頼があれば
`feeds.json` から該当媒体を外す。

## 上のメニューの出し入れと、お気に入り（`docs/ui.js`）

`docs/ui.js` は**6つのニュースサイトで同じものを使っている共通ファイル**。

- **下にスクロールすると上のメニュー（見出し＋絞り込み）が隠れ、一番上に戻すと出る。**
  隠すのは見出しの高さを過ぎてから、戻すのは一番上に着いたときで、しきい値を分けて
  境目でちらつかないようにしている。
- **記事カードの右上の ☆ を押すとお気に入りに入り、「★ お気に入り」タブでまとめて読み返せる。**
  タブは絞り込みの1段目、「すべて」のすぐ隣に入る（末尾に足すと横スクロールの外に出て気づかれない）。
  詳細ページ（`a.html`）にも「☆ お気に入り」が出る。

ページ側に足してあるのは次の4つだけ。

| 場所 | 中身 |
| --- | --- |
| `<head>` | `<script src="ui.js" data-site="akita-news"></script>`（**`defer` を付けない**） |
| `render()` | 記事カードを `<article data-id="${escapeHtml(item.id)}">` にする |
| `load()` | `all = window.NEWS_ITEMS = data.items || [];` |
| リンクの決め方 | このサイトは全記事が元記事へのリンクなので、`window.NEWS_LINK` は置いていない（`ui.js` の既定と同じ） |

**気をつけること:**

- **`ui.js` は6サイトに同じ内容のコピーが置いてある。** 直すときは全部に配り直す。
  数え方は `md5 -q */docs/ui.js | sort -u | wc -l`（1なら揃っている）。
- **`data-site` を必ず入れる。** お気に入りは localStorage に持っていて、6サイトとも
  `mifune39428.github.io` の同じドメインにあるため、これが無いと互いのお気に入りが混ざる。
  URLから機械的に決めると、一覧（`/`）と詳細（`/a.html`）で別のキーになってしまう。
- **`<script>` に `defer` を付けない。** 付けると、詳細ページの `fetch` のほうが先に終わったときに
  `uiAttachDetail` がまだ無く、お気に入りボタンが付かないことがある。
  画面をいじる処理は `DOMContentLoaded` まで待つので、`<head>` に置いても表示は遅くならない。
- **お気に入りは記事のIDではなく記事そのものを写して持つ。** 一覧は30〜45日で入れ替わるので、
  IDだけ覚えても後から中身が引けない。入れ替わりで消えた記事は「掲載終了」と出し、
  解説ページではなく元記事へのリンクにする。

### 端末をまたぐお気に入りの同期（GitHub Gist）

お気に入りは各ブラウザの localStorage に入るので、そのままでは端末をまたげない。
**GitHub の非公開Gist 1個**に預けて、iPhone でも Mac でも同じ★が出るようにしてある。

- 端末ごとに1回だけ、`gist` 権限のトークンを「★ お気に入り」タブ →「ほかの端末と共有する」から貼る。
  トークンは**6サイト共通**（同じドメインなので分けても意味がない）。1回入れれば6サイトに効く。
- Gist は**説明文の目印 `newsfav-sync` で探す**。Gistのidを持ち歩かなくていいので、
  新しい端末はトークンを貼るだけで既存のGistを見つけられる。6サイトぶんを
  `favorites-<repo名>.json` という別ファイルで1つのGistに入れる（PATCHで自分のファイルだけ触る）。
- **消したことも覚えておく**（`removed` に消した時刻）。これが無いと、片方の端末で外した★が
  もう片方の端末の古い控えで復活する。付け直した時刻のほうが新しければ★は残る。
  墓標は180日で捨てる。
- 送る前に必ず読んでから混ぜる（read-modify-write）ので、2台で同時に触っても片方が消えない。
  取りに行くのは「開いたとき」「戻ってきたとき」「★を押した1.2秒後」。
- 圏外でも★の付け外しは手元で動き、つながったときにまとめて送られる。
- トークンを使いたくないときは、設定画面の「トークンを使わずに手で移す」から
  文字列をコピーして別の端末に貼る。

**トークンの置き場所について:** `mifune39428.github.io` に置いたページからはどれでも読める
localStorage に入る。`gist` 権限だけ・期限付きのトークンを使うこと。要らなくなったら
GitHub 側で失効させれば、その端末の登録も無効になる。
